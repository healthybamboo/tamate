# 解錠仕様

`tamate` は「開けないメモアプリ」である。書いたメモはすぐには読めず、開こうとしてから
一定時間待たないと本文が表示されない。この文書はその解錠まわりの決定事項をまとめる。
実装（`lib/features/memo/domain`）はこの文書を正とする。

## 用語

| 用語 | 意味 |
| --- | --- |
| ロック中 | まだ開こうとしていない状態。本文は読めない |
| 待機中 | 開こうとして計測が始まり、解錠条件を満たすまでの状態。本文は読めない |
| 解錠中 | 解錠条件を満たし、本文が読める状態 |
| 待機時間 | 解錠条件を満たすまでに必要な時間。メモごとに設定する |
| 経過 | 待機画面を見ていた時間。画面を離れた時点で捨てる |
| 開封 | 本文が読める状態になること。回数と日時を記録する |
| 問いかけ | 開く前に自分へ投げる問い。メモごとに複数登録できる |

## 決定事項

### 待機の起点

**一覧からメモを開いた時刻**を起点とする。読みたくて開いたのだから、そこから数え始めて
よい。一覧を眺めているだけでは始まらない。

再ロックされたあとだけは、画面にいても自動では始めない。読み終えた直後にまた待たされて
いるのは意図と違うので、「開く」を押したときに始める。

### 待機時間

**メモごとに設定する。** 選択肢は次の4つで、既定値は3分。

- 1分 / 3分 / 5分 / 10分

1日待たせるような長さは、書いた側も読む気を失う。待たされている感覚が残るのは
せいぜい10分までなので、上限を10分にしてある。

待機時間は作成時に決めるが、**解錠中なら後から変えられる**。変えるには一度開く必要が
あり、そのコストは払っているので、あとは育てていけるようにしておく。ロック中・待機中は
変えられない。

### 画面を離れたときの挙動

**待機は最初からやり直しになる。** 一覧に戻る・アプリをバックグラウンドに送る・アプリを
落とす、のいずれでも経過を捨てる。

これは、このアプリで払ってほしいコストが経過時間ではなく**その時間を待つことに使う意思**
だから。止めて再開できると「ちょっと離れる」ができてしまい、待っていない時間が待機に
数えられてしまう。画面に張り付いてでも読みたいものだけが読めればいい。

「待つのをやめる」も画面を離れるのと同じ扱いで、経過を捨ててロック中に戻す。

解錠したあとも同じで、画面を離れればその場で閉じる。

### 端末時刻の扱い

**端末時刻を進めて待機を飛ばせることは許容する。** データは端末内にしか無く、守るべき秘密が
あるわけでもないので、時刻の巻き戻し検知や単調増加クロックの導入は行わない。
残り時間は素直に `DateTime.now()`（実装上は差し替え可能な `Clock`）で計算する。

なお、時刻を巻き戻した場合は残り時間が伸びる。これも許容する。

### 解錠後

**詳細画面を開いている間だけ読める。** 画面を離れた時点で閉じ、次に読むにはまた待つ。
開いている間はそのままで、時間で追い立てることはしない。

待機と同じで、一覧に戻る・アプリを背面に送る・アプリを落とす、のいずれでも閉じる。

### 編集

**解錠中のみ編集できる。** 本文・問いかけ・待機時間・解錠のしかたのすべてが対象。
ロック中・待機中は本文の表示も編集も不可。
タイトルは常に表示・編集の対象外とし、一覧でも詳細でも表示する（どのメモか分からないと
開きようがないため）。削除は状態にかかわらずいつでもできる。

### 通知

**使わない。** 待機は待機画面を見ている間しか進まないので、解錠の瞬間には必ず画面を
見ている。知らせる相手がいないため、通知そのものと権限の要求をやめた。

通知は**解錠時刻ちょうどに出す**。「あと1分」と表示しておいて数分後に知らせるのでは
待つ体験が崩れるため、Android では正確なアラーム（`SCHEDULE_EXACT_ALARM`）を使う。
Android 14 以降はユーザーの許可が要るので、待機を始めるときに一度だけ求める。
許可されなかった場合は精度を落として予約する（通知は遅れることがあるが、画面上の
残り時間は現在時刻から計算しているのでズレない）。iOS はもともと時刻どおりに出る。

### 問いかけ

待たせたいのは時間そのものではなく、**その行動を選び直す余地**を作るため。であれば、時間の
代わりに問いに答えさせる形も成立する。作成時に解錠のしかたを3つから選べるようにする。

| 種類 | 解錠の条件 |
| --- | --- |
| 待つ | 待機時間ぶん待つ |
| 待つ + 問いかけ | 待機のあとに問いへ答える |
| 問いかけだけ | 待たずに、問いへ答えれば開く |

- 問いは**待ち始める前**に出す。待ってから聞くのでは、引き返す機会として遅い
- 問いはメモごとに**複数**登録する。登録した順に1問ずつ出し、全部に答えると待機が始まる
- 答えるのにかけた時間は待機に数えない。待機は答え終えた時点から始まる
- 順番は固定。「後悔しないか」→「目を瞑って本当にそうか」のように、前の問いを受けて
  次の問いを置けるようにするため
- 答えは「はい / いいえ」の2択
- **「いいえ」を選んだらその場で閉じ、ロック中に戻る**。待機の経過もリセットするので、
  次に開くときは最初から。答えを撤回して押し直す余地を残さないため
- 引き返した記録（日時）を残し、開封の記録と並べて振り返れるようにする
- 問いの文言は作成時に書く。よく使う問いは候補として出す。解錠中なら後から直せる

### 4桁のコードの生成

このアプリは「開けなくする」ものではなく「開きにくくする」もので、解錠に何かを
入力させる仕掛けは持たない。4桁の数字は**アプリの外のシステムに設定するコード**を
作るための機能として置く。

想定しているのはスクリーンタイムのパスコードのような、**覚えていては意味がない**値。

1. 作成画面で「4桁のコードを生成」を押すと、本文が生成された4桁に置き換わる
2. その値を設定したいところ（スクリーンタイムなど）に入力する
3. 保存する。以降は他のメモと同じで、読み直すには待つことになる

生成された値は保存するまでは画面に出したままにする。設定先に入力する必要があるため。
保存したあとは本文なので、待機が明けるまで読めない。忘れるのはユーザーの仕事で、
アプリは覚えておく側に回る。

### 開封の記録

本文が読める状態になった時刻を、メモごとに履歴として残す。回数はその件数で数える。

- 記録するのは「読めるようになった瞬間」。閲覧可能時間の内側で画面を出入りしても増えない
- 再ロックされたあとにもう一度開けば1件増える
- 履歴と回数は、ロック中でも詳細画面から見られる（本文ではないので隠す理由がない）

履歴は羅列だけでなく、**横軸を日付・縦軸を時刻（0〜24時）とした図**でも見せる。同じ枠に
複数回あれば色を濃くする。いつ頃開きがちか、どの日に集中したかを後から読み取れるようにする。

図の横幅は記録のある日まで伸ばし、左に辿れば古い記録まで遡れる。記録が少ないうちも
2週間ぶんは出す。遡れるのは1年前まで。

### 開封回数に応じた提案

開きすぎているメモには、詳細画面で提案を出す。どちらも「あとで」で閉じられる。
閉じてもその場で消えるだけで、次に開けばまた出る。

| 開封回数 | 出す提案 |
| --- | --- |
| 3回以上 | 待機時間を1段階のばす（1分 → 3分 → 5分 → 10分） |
| 5回以上 | 上に加えて、内容の見直しか削除 |

解錠中なら編集からも変えられるが、この提案はその場で1段階のばすだけの近道として置く。
従うかどうかはユーザーが決める。

### 将来の仕掛け

待機時間以外の解錠条件（場所、回数など）を後から足せるよう、解錠条件は `UnlockRule`
として抽象化する。追加時は `UnlockRule` の実装を1つ増やし、`UnlockRule.fromJson` に
分岐を足すだけで済むようにする。組み合わせが必要になったら、そのときに合成用の実装を
足せばよい。

`UnlockRule` は解錠時刻を返せるとは限らない。返せない場合は通知を予約せず、解錠を
検知した時刻を `Memo.unlockedAt` に記録して閲覧可能時間の起点にする。

## 状態遷移

```
        ┌──────────── 待機を中断 / 閲覧可能時間が経過 ────────────┐
        │                                                        │
   ┌────┴─────┐   「開く」   ┌──────────┐   解錠条件を満たす   ┌────┴─────┐
   │ ロック中  │ ─────────→ │  待機中   │ ─────────────────→ │  解錠中   │
   └──────────┘             └──────────┘                     └──────────┘
```

状態はすべて `Memo`（`unlockRule` / `wait` / `unlockedAt`）と現在時刻から導出する。
導出は `Memo.lockStateAt(DateTime now)` に閉じ込め、UI では時間計算をしない。

`wait` は待機を始めた時刻を持つだけでよい。画面を離れれば捨てるので、残り時間は
「待機時間 − (現在時刻 − 開始時刻)」で足りる。

## 保存形式

`SharedPreferences` に JSON 配列で保存する。既存データにフィールドが無い場合の扱いは次の通り。

| フィールド | 欠けているとき |
| --- | --- |
| `unlockRule` | 既定の待機時間（10分）のルールとして読む |
| `unlockRule.type` が未知 | 同上（将来のバージョンで作られたデータを読んでもクラッシュしない） |
| `wait` | `null`（ロック中）。起動時にはいずれにせよ捨てる |
| `unlockedAt` | `null`（起動時にはいずれにせよ捨てる） |
| `answeredAt` | `null`（まだ問いに答えていない） |
| `openedAt` | 空の履歴（開封回数0回として扱う） |
| `declinedAt` | 空の履歴（引き返した回数0回として扱う） |
